# gfa-geo（GEO 内容改写器）

## Purpose

帮内容创作者把"写给人看"的文章，改写成"写给人看、也被 AI 引擎引用"的版本。
不改变原意、不编造事实，只按已被验证的 GEO（Generative Engine Optimization）机制，
提升内容在 ChatGPT / Perplexity / AI Overviews 等生成式答案中被引用的概率。

核心立场：**GEO 优化是给内容加"可信信号"，不是刷关键词**。任何为被引用而伪造数据/
假引用的做法，都被本 skill 硬性禁止。

## 理论内核：阳明心学 · 致良知

本 skill 绑定唯一理论内核「致良知」，操作化为两条判据，贯穿全流程：

1. **良知红线（管可信）**：所有统计数据、专家引述、外部引用必须真实可查。
   绝不为提升引用率而编造数字、虚构来源、张冠李戴。AI 一旦引用假信息，
   摧毁的是你整个信源可信度——这是不可逆的。
2. **知行合一（管有效）**：改写不是自嗨。每处改动必须能说清"对应哪条 GEO 策略、
   预期提升哪个维度"；交付后鼓励回填真实 AI 引用率，让判据随实战进化
   （对接回填闭环，见 Red lines 第 6 条）。

## When to use

- 用户说：GEO 优化 / 生成式引擎优化 / 让 AI 能搜到 / 被 AI 引用 / 搜索可发现性改写 /
  AI 搜索可见性 / 提升 AI 引用率 / 内容 GEO 化 / 让 ChatGPT 推荐
- 用户给了一篇文章/笔记/落地页文案，希望它在 AI 搜索里更常被提到
- **注意区分**：用户说"去 AI 痕迹 / 降 AI 检测率 / 不像 ChatGPT 写的" → 那是去 AI 味，
  不是本 skill；GEO 是"让 AI 引擎愿意引用你"，二者方向相反，不混用。

## Workflow

### 1. 确认输入与目标 — 🟠 GATE（场景自适应）

- 原文**缺失** → 停下，向用户要原文（🟠 必问，无默认）。
- 原文在、目标平台/领域**缺失** → 场景自适应判定：
  - 简单任务（单篇短文、用户只说"GEO 优化"）→ 🔵 默认"通用多平台"，宣布假设："默认按通用多平台改写，如需针对某平台告诉我"。
  - 复杂任务（长文、含对外发布意图、用户提到具体平台）→ 🟠 问平台侧重（给 2–4 选项+推荐）。
- 原文 + 目标都齐 → 🔵 直接进下一步。

### 2. 加载真料知识库 — 🔵 AUTO

读取 `references/知识库.md`（**必读，不得跳过**）。本 skill 的所有策略、增益数字、
平台差异都来自该库，不靠"感觉"。若库未找到，停止并报告，不得空写。

### 3. GEO 诊断扫描 — 🔵 AUTO

按知识库判据扫描原文弱点，输出诊断清单（内部用）：
```
诊断清单：
- 统计数据缺失：<N 处模糊断言待补数字>
- 引用/专家引述缺失：<N 处>
- 回答优先结构：<段首是否直接给答案，Y/N>
- 标题层级：<H2/H3 是否镜像用户问法>
- 新鲜度信号：<有无更新日期，Y/N>
- 反模式命中：<关键词堆砌/无结构/内容空泛 等>
目标平台侧重：<通用 / ChatGPT / Perplexity / AI Overviews>
```

### 3½. 联网采集真实引用（🔵 自适应）

针对诊断出的"缺数据/缺出处"断言，联网搜**真实、对口、近期**的引用（用户原文无自有数据时的主要补给线）：
- **能力检测**：环境具备 WebSearch / WebFetch → 执行采集；不具备 → 🔵 跳过本步，直接走"知识库 + 用户自有数据 + 第三方引用兜底"（不编、不卡）。
- **优先源（主流媒体 + 权威）**：
  - 中文：新华社、人民日报、央视新闻、财新、第一财经、36氪、虎嗅、钛媒体、界面新闻、澎湃新闻、中国新闻网、环球网、腾讯新闻、新浪财经；高校/研究机构；行业权威报告（艾瑞、亿欧、QuestMobile 等）；政府/官方文档。
  - 国际/全球话题：Reuters、Bloomberg、AP、NYT、WSJ、The Guardian、BBC 等。
  - **禁用**：SEO 采集站、营销软文号、无出处聚合、论坛猜测帖（AI 不信，且易踩红线）。
- **采集动作**：围绕主题/子话题做 1–3 次定向搜索（如"短视频带货 市场规模 2025 报告"），优先**近 1–2 年**结果；每条记：具体数字 + 来源媒体名 + 发布日期 + 可访问 URL；专家引述带具名者与身份。
- **真实性约束（对接良知红线）**：只用搜索结果里**真实出现**的信息；URL 必须是搜到的真实链接，**不得臆造**；某数字仅出现在低质源且无法交叉验证 → 宁可不用。
- **产出**：一份"真实引用池"（内部用），供 Step 4 按增益排序选用。

### 4. 改写执行 — 🔵 AUTO（受强约束的创意步骤）

基于诊断清单 + 知识库九策略 + 五模式改写。铁律：
- **只加信号，不改事实**：数字、案例、观点、原文立场一律不动；新增的统计数据/
  引述/来源必须是用户原文已含、用户另行提供、或 Step 3½ 联网搜到的真实引用池中的信息——**禁止虚构**。
- **按增益排序优先做高杠杆项**：专家引述(+41%) > 统计数据(+33%) > 引用来源(+28~115%)
  > 流畅度(+29%) > 权威语气/易读/专业术语。每处改动标注所用策略。
- **回答优先**：每段首句直接给结论（LLM 段首抽取多 2.3 倍）。
- **事实密度（口语化，反论文腔）**：模糊断言→具体数字，但**说人话**：
  - **背书性数字**（为增强可信度引用的统计/研究数字）→ 口语化表达（"七成三" > "73%"、
    "四十多项研究" > "44 项研究"），精确值+出处（研究名/机构/年份/链接）下沉到
    **文末「数据来源附注」**，不写进正文括号。
  - **业务关键数字**（价格/规格/日期/数量，读者决策必需）→ 保留精确值，正常呈现。
  - 正文禁止"（HubSpot 2025）"式出处括号堆砌——精确数字堆砌=论文腔，违反红线第 8 条。
- **内联引用（出处形态按平台）**：正文可标注"据某机构"的**来源名**（保持叙述自然），
  但**详细出处（研究名/原数字/链接）一律进文末「数据来源附注」**：
  - 通用 / AI Overviews：正文只用口语化来源名（"据世界卫生组织"），链接进附注。
  - Perplexity（要求逐句溯源）：句尾可紧跟真实来源链接，但**不写"（研究名+年份）"标签**。
- **结构化**：H2/H3 用词贴近用户会键入 ChatGPT 的问法。
- **反模式禁用**：不堆关键词、不写无数据空话、不制造内容与事实矛盾。
- **平台化模板（按目标平台套用，最大化文本层 GEO）**：
  - **ChatGPT**：一页内覆盖该话题的所有子问题（用 H2/H3 设问），让用户一个问题进来不用跳走；每段给"近 2 年"新鲜信号（标注数据年份）；自然嵌入 Wikipedia / Reddit / 官方文档类权威外链。
  - **Perplexity**：每个论断后紧跟"来源：<真实可查链接>"，引用透明到能逐句溯源；多用被密集引用的权威源。
  - **AI Overviews（谷歌 AI 概览）**：必加 **FAQ 段**（问句作 H3，答案 2–3 句直接给）+ **HowTo 段**（步骤列表化）；结构化程度越高越易被抽作"标准答案"。
- **第三方引用兜底（无自有数据时）**：若原文无任何真实数据/专家、用户也无法提供 → **绝不编数字**，改为显式提示用户"你这篇目前 0 个可引用信号，建议引用以下真实第三方权威源（政府/大学/行业报告/官方文档），并把链接贴到文中"，并列出 2–3 个真实存在的权威源供其核对引用。
- **时效性声明**：知识库 §3 的 Princeton +40%/+41%/+33% 等增益为 **2024–2025 年实测**，仅作"相对强弱排序"参考，不代表今天精确增益；改写时引用数据务必用**最新年份**的真实数字，并向用户注明"数据年份"。

输出三栏对比（原文 / 改后 / 为什么改），并附改后全文：
```
| 位置 | 原文 | 改后 | 对应 GEO 策略 | 预期增益 |
|------|------|------|--------------|---------|
| 第2段 | ... | ... | Statistics Addition | +33% |
...
=== 改后全文 ===
<完整改写稿>

=== 数据来源附注（每次交付必附）===
把正文里用到的**每条背书性数字**的精确出处列出来（供 AI 索引 + 用户核对）：
- <数字口语化表述> → 精确值 + 来源机构/研究名 + 年份 + 真实链接
- 每条一行；正文已保留精确值的业务关键数字不必重复。
此附注与「小白技术层说明」并列，是交付物固定组成，不得省略。
```
**边界声明**：本步是"策略命中数"对比，**不等于真实 AI 引用率**。GEO 是概率提升，
不承诺 100% 被引；建议用户发布后用知识库第 10 节指标实测回填。

**每次交付必附「小白技术层说明」**：在改后全文下方，强制追加一栏「📋 你还得做的技术动作（小白版）」，
用大白话讲清文本层之外、技术侧还需落实的事（robots 爬虫权限 / Schema 标签 / 更新日期 / 页面可被搜到）。
模板见本 skill 末尾「小白技术层说明」章节。**此栏只解释、不写代码、不替你操作。**

### 6. 验收打分 — 🔵 AUTO（反馈闭环）

对改后稿按 KPI 维度打分（0–10），任一项 < 6 自动给出补强建议：
```

引用信号：内联引用/专家引述 __ 处（目标 ≥2）→ <建议>
回答优先：段首直接给答案占比 __%（目标 ≥70%）→ <建议>
新鲜度：是否含更新日期 __ → <建议>
红线合规：无伪造/无堆词 __ → <若命中立即回修>
```
低于阈值不强制停，但必须列出"还差什么"，让用户决定是否加。

## 小白技术层说明（每次交付必附，小白能懂）

> 文本层 GEO 做得再满，技术层挡着也白搭。本栏是交付时**必附**的"人话版技术清单"，
> 直接复制到你的交付末尾。只解释"你还得做什么、去哪做、问谁"，**不写代码、不替你改网站**。

### 模板（按需勾选，逐条用大白话）

**① 让 AI 爬虫能进你的页面（最关键，否则前面白做）**
AI 公司要用"爬虫"来读你的文章。你的服务器/建站后台有个叫 `robots.txt` 的小门禁，
默认可能把 AI 爬虫挡在门外。被挡了，你文章写得再好 AI 也看不到。
- 你要确认这几个"客人"被放行：ChatGPT(GPTBot)、Google AI 概览(Google-Extended)、
  Perplexity(PerplexityBot)、Claude(ClaudeBot)。
- 小白动作：在后台 / CDN / 服务器面板搜"爬虫"或"robots"，把上面几个名字加进**允许**名单；
  不会弄就问建站工具客服："怎么允许 AI 搜索引擎抓取我的网站？"

**② 给页面贴"结构标签"（Schema 结构化数据）**
AI 喜欢"贴了标签"的内容。FAQ 页贴 FAQPage 标签、教程贴 HowTo 标签、文章贴 Article 标签，
AI 更容易把你当标准答案抽走。
- 小白动作：用 WordPress / 公众号 / 建站工具 → 搜"结构化数据插件"一键开；
  或让技术加几行标签（本 skill 不替你写代码）。

**③ 标"最后更新"日期（新鲜度信号）**
AI 更信"最近更新"的内容。页面写清"最后更新：2026-XX-XX"比没日期更受信任。
- 小白动作：在文章顶部或底部加一行更新时间，手动改就行。

**④ 文中加 1–2 个权威外链**
引用政府 / 大学 / 大媒体 / 官方文档的链接，AI 认为你"有依据"。
- 小白动作：文末或句中加真实存在的权威链接（别链来历不明的站）。

**⑤ 页面本身要能被搜到**
加载快、已被搜索引擎收录（没被"noindex"挡成草稿）、有内部链接互相串。
- 小白动作：确认文章是"公开发布"不是草稿；用搜索引擎站长工具提交网址。

**收尾一句（复制给用户的白话）**：
"上面的①是必须的——AI 爬虫进不来，前面改得再好也白搭。②③④是加分项，
能帮你被引用的概率再上一个台阶。这些都不用你写代码，要么在后台点几下，要么让技术 / 客服帮一下。"

## KPI（输出打分维度，每项 0–10）

1. **数据密度**：带源具体数字数量（越多越易被抽取引用）
2. **引用信号**：内联引用 + 专家引述覆盖度
3. **可抽取性**：回答优先结构 + 标题设问化占比
4. **红线合规**：真实无伪造、无关键词堆砌、无事实改动（此项一票否决，命中即 0 分回修）

任一项 < 6 → 自动建议补强项。

> **（v1.2 新增）联网搜来的引用额外核对**：来源是否主流媒体/权威机构、是否近期（时间敏感话题优先 ≤2 年）、URL 是否真实可访问、数字是否归对出处。任一不达标则该处引用降级或丢弃，不凑数。

## Red lines（硬红线，违反即重做）

1. **不伪造数据/引用/专家原话**（良知红线，不可逆信任损害）。
2. **不改原文事实、案例、观点、立场**——只加可信信号。
3. **不堆关键词**（GEO 下 -10%，明确有害）。
4. **不承诺 100% 被 AI 引用**（概率提升，非保证）。
5. **不注入 Schema 代码**（技术层，本 skill 仅给建议，由用户技术侧落地）。
6. **回填闭环**：鼓励用户发布后回填真实 AI 引用率/ bot 日志，用于修正判据
   （防理论只会解释不会长大）；无数据时不强行要求。
7. **联网搜到的引用必须真实且归对出处**：只用搜索结果中真实存在的来源与 URL，
   不得臆造链接、不得把 A 媒体的数据说成 B 媒体、不得把搜索摘要当既成事实
   （需可溯源）；低质源且无法交叉验证的数字宁可不用。
8. **反论文腔（数据口语化，2026-08-23 用户红线）**：背书性数字必须口语化呈现，
   精确出处（研究名/原数字/链接）一律进文末「数据来源附注」，不得以
   "（某研究 2025）"式括号堆在正文；业务关键数字（价格/规格/日期）除外。违反即重写该处。
