## 1. GEO 是什么（定义与起源）

**GEO（Generative Engine Optimization，生成式引擎优化）**：优化数字内容，使其在生成式 AI 引擎（ChatGPT / Perplexity / Google AI Overviews / Claude / Gemini）生成答案时，被**选中、引用、复述**。

- 起源：Princeton + Georgia Tech + Allen Institute for AI + IIT Delhi 联合研究，论文《GEO: Generative Engine Optimization》发表于 **ACM SIGKDD 2024**（Aggarwal et al.）。
- 实验规模：跨 **10,000 条查询**测试 9 种优化策略，基准集 GEO-bench。
- 核心发现：添加统计数据、专家引述、引用来源，可使内容在生成式引擎回答中的可见度提升**最高 40%**。
- 来源：[Paz.ai GEO 词条](https://www.paz.ai/glossary/generative-engine-optimization-geo) · [Helium10 综述](https://www.helium10.com/blog/how-to-get-your-products-discovered-in-chatgpt-rufus-and-beyond/)

## 2. GEO 与 SEO 的本质区别（决定了改写逻辑不同）

| 维度 | SEO | GEO |
|---|---|---|
| 检索机制 | 图遍历（PageRank，反向链接 + 域名权威） | 向量相似度（embeddings，语义匹配） |
| 排名单位 | 网页 | 内容块 chunk（约 300–800 tokens） |
| 输出形态 | 10 条蓝链列表 | 合成答案 + 内嵌引用 |
| 目标 | 用户点击进源站 | 用户原地读答案 |
| 新鲜度模型 | 爬取节奏 | 时效信号 + ISO 时间戳 |
| 主信号 | 反向链接 + DA | 实体权威 + 语义相关 |

**关键结论**：GEO 是 SEO 的**超集**（不是替代）。强 SEO 基础支撑 GEO，但 GEO 额外要求结构化数据、实体清晰度、第三方引用、AI 可读架构。关键词堆砌在 GEO 下**无效甚至有害**。

- 来源：[RankAsAnswer 2026 框架](https://www.rankasanswer.com/blog/generative-engine-optimization-geo) · [Devstars 2026 指南](https://www.devstars.com/blog/what-is-geo)

## 3. Princeton 九策略及增益（核心武器库）

> 数字来自不同研究的实测区间，差异源于测试集与平台不同；**相对排序稳定**：引述/数据/引用 >> 流畅/权威/易读 >> 堆词（负）。
> **时效性**：下表增益为 **2024–2025 年实测**，仅作"相对强弱排序"参考，不代表今天精确增益；实际改写引用数据须用最新年份真实数字。

| 策略 | 做法 | 可见度增益 | 备注 |
|---|---|---|---|
| **Quotation Addition 专家引述** | 加入具名、有资历者的原话 | **+41%**（Foxish）/ +30%（Paz） | 单一最有效策略 |
| **Statistics Addition 统计数据** | 模糊断言 → 具体带源数字 | **+33%**（Foxish）/ +37%（Paz） | 第二强 |
| **Fluency Optimization 流畅度** | 提升语法/连贯/可读性 | +29%（Foxish） | 与统计组合 > 单策略 5.5% |
| **Cite Sources 引用来源** | 内联标注可信外部来源 | +28%（Foxish）/ 综合 +40%（Paz） | 对**排名靠后页面**最高 **+115%**（黑马优势） |
| **Authoritative Tone 权威语气** | 自信、有数据支撑的断言 | +25%（xSeek） | |
| **Easy-to-Understand 易读** | 简化复杂内容 | +20%（xSeek） | |
| **Technical Terms 专业术语** | 加入领域专有词汇 | +18%（xSeek） | |
| **Unique Words 罕见词** | 词汇多样性 | 中等（各研究未单列强增益） | |
| **Keyword Stuffing 关键词堆砌** | 传统 SEO 式重复关键词 | **-10%**（有害） | 明确拖后腿 |

**组合效应**：Fluency + Statistics 组合比任何单策略高 5.5%（Novaralabs）。无单一万能策略，需按领域/内容类型组合。

**领域差异**（推测，来自 Novaralabs 实测）：
- 法律/政府类：统计增益最大
- 人文/历史类：引述增益最大
- 解释类查询：引用来源增益最大
- 排名靠后页面：引用来源策略的边际收益最高（+115%）

- 来源：[Foxish Princeton 解读](https://www.foxish.ai/blog/princeton-geo-study) · [xSeek 2025 Playbook](https://www.xseek.io/learnings/how-can-you-control-brand-visibility-on-ai-search) · [Novaralabs 指南](http://novaralabs.tech/blog/generative-engine-optimization-guide) · [Paz.ai](https://www.paz.ai/glossary/generative-engine-optimization-geo)

## 4. 2026 五大支柱（RankAsAnswer 框架）

1. **Semantic Context 语义语境**：从关键词瞄准转向概念深度。每段自包含（不依赖相邻段也能回答问题），段首前置核心结论，用词精确具体，覆盖整个主题簇的多相关问题。
2. **Entity Presence 实体存在**：围绕具名实体（人/组织/产品/概念）建主题权威，而非关键词簇。用 DefinedTerm schema、sameAs 链（Wikidata/Wikipedia）、Person/Product schema。
3. **Extractability 可抽取性**：干净 HTML、回答优先段落，降低 AI 抽取难度。
4. **Citation Network 引用网络**：跨平台共引信号（被其他可信源引用）。
5. **Freshness 新鲜度**：Schema 中 datePublished + dateModified + 可见"最后更新"日期。

- 来源：[RankAsAnswer 2026 框架](https://www.rankasanswer.com/blog/generative-engine-optimization-geo)

| 平台 | RAG 行为要点 | 改写侧重 |

## 6. 内容工程五模式（让页面 citation-ready）

1. **Answer-first**：每段开头直接给答案。LLM 从段首抽取比段中多 **2.3 倍**（Stanford "Lost in the Middle", Liu et al. 2023）。
2. **Fact-dense（口语化，反论文腔）**：每个模糊断言换成数字，但**说人话 + 出处下沉附注**：
   "很多公司用 AI" → "七成三的企业计划今年底前优化 AI 答案（来源见文末附注）"。
   正文不写"（HubSpot 2025）"式括号；精确值+出处（研究名/年份/链接）进文末「数据来源附注」。
3. **Scannable headings**：H2/H3 镜像自然语言问题（用户键入 ChatGPT 的措辞），提升 RAG 段匹配概率。
4. **Canonical data blocks**：价格/规格/SKU/营业时间汇总成表格或列表，机器可读、稳定格式。
5. **Inline attribution**：每个论断在正文内联标注出处（"据 WHO 数据显示"），比文末参考文献增益大。

- 来源：[xSeek 2025 Playbook](https://www.xseek.io/learnings/how-can-you-control-brand-visibility-on-ai-search)

## 7. Schema 类型（技术层，本 skill 仅给建议不做注入）

- 基础：Organization、Article（建实体清晰度与作者身份）
- 内容型：FAQPage（常见问题）、HowTo（流程）、Product（规格/价格）、LocalBusiness（实体位置）
- 必填字段：author、datePublished、dateModified、sameAs（链官方档案 LinkedIn/Crunchbase/Wikipedia）
- 校验：Google Rich Results Test；Schema 与可见正文一致（矛盾会被引擎跳过）
- **小白一句话**：Schema 就是给页面"贴标签"，让 AI 知道"这是 FAQ / 这是教程 / 这是文章、作者是谁"。文本层做不了，得技术侧落地（详见 SKILL.md「小白技术层说明」）。本 skill 只建议、不写代码。
- 来源：[xSeek 2025 Playbook](https://www.xseek.io/learnings/how-can-you-control-brand-visibility-on-ai-search)

## 8. E-E-A-T 适配（AI 用作信源质量标准）

Google 提出的 **E-E-A-T**（Experience 经验 / Expertise 专业 / Authoritativeness 权威 / Trustworthiness 可信）被 AI 引擎用作评估信源质量的标准。生成式引擎为保证可信度，必须提供答案来源——这恰是 GEO 转化的关键：内容越符合 E-E-A-T，越易被采纳引用。

- 来源：艾瑞咨询《GEO 生成式引擎优化行业研究报告 2026》（ima 知识库条目）

## 9. 反模式（绝对不要做）

1. **关键词堆砌**：GEO 下 -10%，且降低清晰度。AI 看语义不数词频。
2. **模糊断言无数据**："显著提升" → 必须给数字，否则被忽略。
3. **无引用/无专家**：缺第三方验证信号，AI 不信任。
4. **无新鲜度日期**：LLM 把新鲜度当信任信号；无 dateModified 易被判过期。
5. **内容与 Schema 矛盾**：可见正文与结构化数据不一致，侵蚀引用置信度。
6. **编造数据/假引用**：违反良知红线，且一旦被发现摧毁信任（本 skill 硬禁止）。
7. **论文腔/数字堆砌**：正文堆"（XX 研究 2025）"式精确出处括号、贴研究标签——读感差，
   违背 2026-08-23 用户红线；背书性数字须口语化，精确出处进文末附注。

- 来源：综合上述各研究

## 10. 测量指标（改写后验证用）

- **AI 引用率**：相关提示词中品牌出现在 AI 答案的百分比
- **AI bot 日志**：识别 GPTBot / Google-Extended / PerplexityBot / ClaudeBot 爬取频率
- **Share of voice**：在语义相关提示词簇中的占比
- **Assisted conversions**：AI 发起会话带来的辅助转化
- 复盘节奏：高流量页 ≥ 每 90 天；快变内容（价格/合规/规格）每月。
- **小白怎么测（无后台也能做）**：① 手动在 ChatGPT / Perplexity 里问你这篇覆盖的问题（如"推荐 XXX"），看答案有没有提到你 / 你的品牌；② 让技术或服务器商查访问日志里有没有 GPTBot / Google-Extended / PerplexityBot / ClaudeBot 的来访记录；③ 隔 2–4 周复测一次，记录"出现→没出现"的变化。

- 来源：[xSeek 2025 Playbook](https://www.xseek.io/learnings/how-can-you-control-brand-visibility-on-ai-search)

## 12. 联网采集优先源与禁区（Step 3½ 用）

> 当原文无自有数据、需联网搜真实引用时，按此优先级取源；本库是"引用质量底座"，与 Step 3½ 联动。

**优先源（主流媒体 + 权威，越靠前越优先）**
- 中文主流媒体：新华社、人民日报、央视新闻、财新、第一财经、36氪、虎嗅、钛媒体、界面新闻、澎湃新闻、中国新闻网、环球网、腾讯新闻、新浪财经。
- 权威机构：高校/研究机构（清华、北大、中科院等）、政府/官方文档（统计局、工信部、央行等）、行业权威报告方（艾瑞、亿欧、QuestMobile、CNNIC 等）。
- 国际/全球话题：Reuters、Bloomberg、AP、NYT、WSJ、The Guardian、BBC。
- 具名专家/企业官方博客（带身份、可核实）。

**禁区（一律不采）**
- SEO 采集站、采集号、营销软文站、无出处聚合页。
- 论坛/贴吧/评论区猜测帖、无法核实的"网友说"。
- 来源模糊（"据知情人士""有数据显示"无具体出处）的内容。

**时效与验证**
- 时间敏感话题（市场/政策/数据）优先取近 1–2 年；常青话题可放宽。
- 每条锁定：具体数字 + 来源名 + 发布日期 + 真实可访问 URL；低质源单点数据无法交叉验证 → 弃用。
