# Skill 工程方法论

## 核心哲学

一个好 skill = **精准触发 + 恰当自由度 + 在正确节点引入人类判断 + 验证闭环**。本 skill 教你用三套工具设计生产级 Agent skill：六要素框架保证 prompt 质量，Anthropic 规范保证可发现与省上下文，决策闸门保证输出稳定不漂移。

## 工作模式

- **先定触发，再写正文**：`description` 是 agent 自动路由的命根子，要塞满触发词。
- **渐进披露**：机械逻辑进 scripts/，知识进 references/，模板进 assets/，SKILL.md 保持精简。
- **闸门克制**：只在高危节点（不可逆/主观/强分叉/高风险）放人类判断，其余自动跑。

## 标准流程（六阶段）

1. **摸清需求**：一句话定"给谁+做什么+何时触发"；模糊则最多问 2 个锐利问题。
2. **定位与命名**：定 name（具体、动词倾向）+ description（第三人称+触发词）+ 能力边界（显式"不做什么"）。
3. **资源架构**：按渐进披露分 scripts/references/assets；按任务脆弱性定自由度（机械锁脚本、创意给方向）。
4. **写正文 + 资源**：写 SKILL.md（祈使语气、<500 行）+ 配套文件；用知识库而非只声明。
5. **布判断节点**：分析新 skill 工作流，按决策闸门规则标哪些步骤需用户判断（🟠/🔵），闸门给"带推荐项的选择题"而非开放提问。
6. **自检 + 验收**：六要素自检表（每项≥4/5）+ 结构校验（frontmatter/字段/命名/一层引用）+ 用户最终确认。

## 六要素（写每个 skill 前对照）

1. 角色清晰 2. 方法明确 3. 知识充分 4. 结构稳定 5. 可被考核 6. 风险可控

## 决策闸门（何时放人类判断）

- 🟠 需闸门：定位/命名（最贵反转）、主观多解（语气/策略/命名）、强分叉（一选驱动大量下游）、高风险（合规/品牌/对外/钱）或缺失无默认的关键输入。
- 🔵 自动：确定性变换、有合理默认、改起来便宜。

## 输出格式（模板 A/B/C）

- **A · skill 设计蓝图**（默认）：name+description+边界 + 资源架构 + 闸门地图 + 六要素自检。
- **B · description 打磨器**：只给 3 个候选 description（带触发词密度评分）供选。
- **C · 闸门地图**：只给"哪些步骤放🟠/哪些🔵 + 每条闸门的选择题模板"。
