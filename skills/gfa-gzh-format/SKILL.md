# 吴唐IP起号之公众号排版

把一段纯文本变成能直接粘进公众号后台的排版图文。**文字一个字都不改**——只加结构（小标题、加粗、引用）和样式；配色和版式只听用户的，不靠内容猜。

## Purpose

解决两件事：① 纯文本贴进公众号是"一坨字"，需要小标题/加粗/引用撑起阅读节奏；② 公众号编辑器会剥掉 `<style>`，必须用行内样式才不掉格式。本 skill 把"语义判断"交给 Agent、"确定性渲染"交给脚本，两者分离。

## When to use

- 用户粘一段文字并说"排版 / 美化 / 弄成公众号格式 / 一键复制"
- 用户说"帮我把这篇文章排成能发公众号的样子"
- 用户给纯文本，要求输出可直接粘贴的图文

不适用：Word/PDF 文件排版（走 office 类 skill）；要改文字内容的润色改写（本 skill 一字不改）。

## 职责边界（谁判断什么）

| 环节 | 谁做 | 规则 |
|---|---|---|
| 识别哪些行是二级标题、哪些词加粗、哪些段落是引用 | Agent 语义判断 🔵 | 按下方判定标准打标记，不改一个字 |
| 配色 / 版式 | 用户选择 🟠 / 默认正红 | **严禁**根据文章内容"推荐"某颜色。默认 red，用户要换才给选项 |
| 文字内容 | 谁都不改 🔵 | 只加标记，不改字、不删字、不纠错（含原文笔误一律保留） |
| 原文快照 vs 标记文本 | 脚本闸门 🔵 | 渲染前逐字比对，标记阶段改了字就**拒绝渲染**（防 Agent 自证） |
| HTML 渲染 / 复制条 / 标注面板 | 脚本 🔵 | 确定性，`scripts/render.py` 完成 |

## 主题（可选清单，脚本不自选）

`red` 正红（默认）· `wine` 酒红 · `vermilion` 朱红 · `ink` 墨黑 · `blue` 商务蓝 · `orange` 暖橙 · `green` 经典绿 · `gray` 浅灰极简。用 `python3 scripts/render.py --list-themes` 查看。

> 用户喜欢红色，默认 `red`。用户说"换颜色/别的色"时，**给上面的选项清单让用户挑**（🟠），不要自己换成墨黑或说"这篇适合商务蓝"。

## Workflow

### 1. 收输入 + 存原文快照 — 🔵 AUTO（歧义才 🟠）
拿到纯文本后，**第一件事：把用户原文一字不改地写入 `source_original.txt`（不可变快照）**，后续所有校验都以它为基准。若用户给了多个文件/多段文字目标不明，列出让用户选（🟠）。否则直接采用。
> 这一步是"文字零改动"的根——没有原文快照，校验就只能拿 Agent 自己的中间产物自证，防不住打标记阶段改字（v1.2.0 实测漏洞）。

### 2. 先读懂文章，再打标记 — 🔵 AUTO

**命门：先理解，后标注。绝不先定数量再凑数。数量是理解之后的结果，不是目标。**

**第一步：通读后先在心里回答三个问题**（内部动作，不输出给用户）：
1. 这篇文章**一句话主旨**是什么？作者到底在主张什么？
2. 作者怎么论证的？分几层？每一层在论证链条里起什么作用？
3. 哪几句是全篇的**骨架**——删掉它们，作者的论证就断了？

**第二步：按理解打标记**，`只加符号不改字`：

- **二级标题** `## `：文章的**论证分节节点**——章节序号行、把论证推进到新一层的转折句。按论证层次切，不按字数切；短文没有明确分节就不标（允许 0 个）。
- **加粗** `**词/句**`：只标**骨架判断**——直接承载作者立场、支撑主旨的结论句。
  - **删掉测试**：把这句遮住，作者的论证还成不成立？成立（只是少个好听的词）→ 不标；不成立（论点缺一环）→ 标。
  - 加粗字色 = 主题色（默认正红），脚本已钉死，不可改回黑字。
- **引用** `> `：只标三类——① 作者自己提炼的、能脱离上下文单独成立的金句或核心比喻；② 作者**引述**的他人说法/流行话术（尤其是后文要批判的）；③ 引述外部规则/数据/出处的段落。
  - **独立测试**：这段单独贴出来还立得住吗？能 → 引用；不能（只是论证过程中的普通一段）→ 正文。
- **正文**：其余行原样，不加任何前缀。
- **铁律**：不改正字、不改标点、不修笔误、不删段、不并段。加粗/引用只加标记符号，标的是**已有的句子**，不是 rewrite。

**第三步：回头自检**（打完标必做）：
- 把所有加粗连起来读——应该能读出**文章的论点骨架**。读不成一句完整的话 = 标到了装饰性内容，重标。
- 把所有引用块连起来读——应该都**独立立得住**。混进了普通论述 = 标错，降级回正文。
- 去掉所有标记后应还原成原文（脚本 `--verify` 会再验一遍）。

**反面教材（用户实测批评过、必须避免）**：拿固定短语列表去硬匹配、按"每段 1-2 处"凑数、见排比就加粗、见短句就引用——那不是理解文章，是给文章贴标签。

### 3. 配色确认 — 🟠 GATE（默认已定则跳过）
默认 `red`，**直接出，不反问**。仅当用户主动说"换颜色/试试别的色/有没有其他排版"时，才给主题选项清单让用户挑（带 `red` 为推荐项）。**任何情况下不得由 Agent 自行决定主题。**

### 4. 渲染 — 🔵 AUTO（带原文快照闸门）
把带标记文本写入 `marked.txt`，调用脚本。**必须带 `--source` 指向第 1 步的原文快照**：

```bash
python3 <skill>/scripts/render.py marked.txt -o out.html --theme red \
  --title "文章标题" --source source_original.txt
```

脚本在渲染**前**逐字比对"标记文本去标记后 == 原文快照"，不一致直接拒绝渲染并打印首个差异位置。产出：全行内样式正文 + 一键复制条 + 标注预览面板（面板在正文 div 外，带 `user-select:none`，一键复制和手动全选都不会带走）。

### 5. 校验 — 🔵 AUTO（闭环，非自证）
```bash
python3 <skill>/scripts/render.py marked.txt --verify out.html --source source_original.txt
```
必须输出 `VERIFY OK：正文文字与基准逐字一致`，且**不带** `WARN: 未传 --source`。不带 `--source` 的校验只能证明渲染没丢字，不能证明打标记没改字——等于自证，不算数。

### 6. 交付 — 🔵 AUTO
用 present_files 打开 HTML 预览。告知：点右上角"复制正文"→ 公众号后台正文区粘贴即可。页面下方的灰色虚线框是标注预览（标了哪些标题/加粗/引用），只给你看、不会被复制。顺带说一句"想换颜色可随时说"（不展开选项，除非用户要）。

## 正反例（基于对文章的理解，不是贴标签）

拿本次这篇文章做示范——先理解它讲什么：**作者讲的是"努力的边界"——互联网给普通人机会，但机会的分配权在平台；依赖平台的生意不牢固，真正该积累的是不随平台规则消失的判断力与信任；机会珍贵但无永久保障，机会过去后仍有选择能力才是关键。**

理解了这个主旨之后，标出来的应该是：

- ✅ **加粗**骨架判断：`我们很容易把时代给我们的机会，误以为全部都是自己的本事`、`在别人的土地上去种自己的树`、`一个人通过平台获得的机会，并不等于他拥有了创造这种机会的权利`、`未来真正稀缺的可能真的不再是知道多少方法，而是能不能判断方法在什么情况下是有效的`——这些删掉，文章的论证就断了。
- ✅ **引用**独立金句：`有些机会，你准备了很久，却没有等到`、`有些事情，你原本没有那么大的期待，反而得到了意想不到的结果`、`当然了，这不意味着我们只能听天由命。也当然，有些事情只能听天由命`——单独拎出来仍立得住，是作者反复锤打的结论。
- ❌ **不该加粗**：`流量很大是一回事，能不能把流量变成生意又是另外一回事`（是解释性过渡，不是论点）、`选对赛道，找到方法，持续执行，然后获得结果`（这是作者**引述**来批判的话术，该做引用不是加粗）。
- ❌ **不该引用**：`当然，这些平台没有全面禁止所有的自媒体知识分享`（普通论述，单独拎出来没有意义）。

先有理解，才有这些判断；反过来套规则是套不出来的。
